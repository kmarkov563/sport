# AI-тренер: с чего начать

Точка входа. Прочитать эту таблицу и поднимать **только** файлы своей задачи — лишний контекст не тянуть. Имеет приоритет над описаниями workflow в других файлах.

AI сам анализирует историю, факт и цели атлета и выбирает всё: упражнения, нагрузку, объём, частоту, горизонт, модель прогрессии.

**Атлет** (`<пол>` во всех путях): «я / мой план» — `man`; жена — `women`; Саня — `sanya`. Неясно — уточнить. Данные атлетов не смешивать.

**Приватный репо `kmarkov563/sport-private`** — личные данные атлета `man`: профиль (рост, вес, жир), привычки питания и сна, журнал веса/сна/талии (`body.csv`) и еды (`food/`). Его `AGENTS.md` — как туда писать. Для планирования (B) и консультаций по `man` (питание, восстановление, «почему тяжело») — клонировать (как — раздел «Git» ниже) и учитывать. Личные цифры в этот публичный репо не писать.

## Маршрут

| Задача | Что читать | Как отвечать |
|---|---|---|
| «Что сегодня?» / ссылка на план | `log/<пол>/index.json` → `currentSessionId` → файл плана по `plans[].sessionIds` → эта сессия. Больше ничего | Кратко по упражнениям: `вес × повторы × подходов, RIR`, без обоснований и техники. Ссылка: `https://kmarkov563.github.io/sport/coach-<пол>.html` |
| Вопрос по ходу тренировки (вес, запас, «что дальше», снаряд занят/сломан) | Один раз за чат: текущая сессия (как строкой выше) + «ПОСТОЯННЫЕ РЕШЕНИЯ» из `requests/<пол>.txt`. Дальше отвечать по ним, повторно не читать | 1–3 предложения. Файлы не править, пока атлет не попросит записать |
| A — записать факт (атлет прислал, что сделал) | `agents/task-record.md` + `agents/data-model.md` | Всегда заканчивается проверкой следующего микроцикла (п. 5 `task-record.md`): построить или сверить; 👍 в Telegram — только после неё |
| B — подготовить / изменить будущие тренировки | `agents/task-plan.md` + `agents/data-model.md` + для `man` — `sport-private`: `profile.md` и тренд веса, сна, талии, белка за 2–4 недели | Цифры оттуда в этот публичный репо не писать |
| D — стойка на руках (навыковый трек мужчины) | `agents/track-handstand.md` | |
| Вопрос: питание, сон, восстановление, техника | Нужный файл из `base/` | Темы нет в `base/` — сказать об этом в чате |
| Вес, сон, талия, еда — записать | Не сюда: приватный репо `kmarkov563/sport-private` | |
| Код сайта, хостинг, оффлайн | `agents/site.md` | Проверку в браузере делает пользователь |

Промт из нескольких задач — по порядку, каждой только её файлы. Типично: A, затем при необходимости B.

## Задачи из Telegram

Сообщения берутся через коннектор Telegram (`get_new_messages`). Ответ всегда в тот же топик, где пришла задача:
- **Сделано** (записано, проверка микроцикла пройдена, всё запушено) — отчёт в Telegram не писать, только `mark_done` (👍) на всю переписку по задаче.
- **Есть вопрос** (что-то неясно, записать нельзя) — `send_message` с вопросом, 👍 не ставить: ответ придёт в следующий `get_new_messages` рядом с задачей.
- **Что-то пошло не так** — не удалось склонировать репо, пуш отклонён и не прошёл после `pull --rebase`, конфликт, ошибка инструмента, план не построился, сделано только частично — `send_message` коротко: что не получилось, на каком шаге, текст ошибки, что успело записаться и запушиться, а что нет. 👍 не ставить, чтобы задача вернулась в следующий раз. Молча не заканчивать.
- Сообщение не про тренировки и делать с ним нечего — просто `mark_done`.

## Git

Чат о тренировке почти всегда заканчивается записью факта (а иногда и новым планом), поэтому репо клонировать сразу, в начале чата (`--depth 1`), и работать с локальной копией.

**Как клонировать** (`sport` и `sport-private` одинаково):
- Облачная сессия (чат проекта в claude.ai, задача по расписанию): сначала подключить репо к сессии — `add_repo` (owner `kmarkov563`, repo `sport` / `sport-private`, access `push`), потом `git clone --depth 1 https://github.com/kmarkov563/<repo>`. Без `add_repo` приватный репо отвечает «not found», а пуш не проходит. SSH здесь нет.
- Claude Code на компе: `git clone --depth 1 git@github-kmarkov563:kmarkov563/<repo>.git` — SSH-алиас есть только там.
- Коннектор GitHub (`mcp__github__*`) для этих репо не использовать: он под другим аккаунтом и приватный репо не видит.

Всё в `main`. Перед правкой — `git pull --rebase origin main`, после каждой правки данных — коммит и пуш. Процесс — `agents/git-workflow.md`. Пользователю о процессе не сообщать, кроме конфликтов.
