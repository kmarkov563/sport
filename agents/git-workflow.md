# Git: ветка `workout` и сохранение изменений

Репо — долгосрочная база журнала. `main` публикуется на GitHub Pages (каждый пуш в `main` = пересборка сайта, мягкий лимит ~10 в час), поэтому по ходу тренировки изменения копятся в отдельной ветке `workout`, а в `main` попадают одним коммитом.

Пользователю про этот процесс не сообщать — делать молча. Говорить только о конфликтах.

## 1. Проверка в начале (каждая сессия, где трогаешь `log/`, `requests/` или планы)

Не нужно, если разговор не касается журнала (вопрос про питание, технику и т.п.) — тогда git не трогать.

```bash
git fetch origin main
git ls-remote --exit-code --heads origin workout   # код 0 = ветка есть
```

Если `workout` есть — это незавершённая тренировка из другого чата/сессии. Влить её в `main` (раздел 3) **до** любых новых правок. Конфликт — остановиться, показать пользователю, что конфликтует, и спросить, как решить.

## 2. По ходу тренировки (правки факта/плана из чата)

- Работать в ветке `workout`, созданной от свежего `origin/main`:
  ```bash
  git fetch origin main
  git switch -C workout origin/main
  ```
- После правок, которые жалко потерять (записанный факт, изменённый план), — коммит и `git push -u origin workout`. Пуш в `workout` не пересобирает сайт, частота не важна; коммит-сообщения короткие, они всё равно схлопнутся.
- Если окружение могло очиститься (новый чат, нет локальной копии) — склонировать заново и продолжить с `origin/workout`, если он есть.

## 3. Конец тренировки — влить в `main`

Триггер: атлет закончил тренировку («всё», «последнее упражнение», итог), либо раздел 1 нашёл висящую `workout`.

```bash
git fetch --depth=200 origin main workout      # нужна общая история для слияния (клон может быть shallow)
git switch -C main origin/main
git merge --squash origin/workout
git commit -m "Тренировка N: <кратко что записано/изменено>"
git push origin main
git push origin --delete workout
git branch -D workout 2>/dev/null || true
```

- Сообщение коммита — как в истории репо: по-русски, кратко, по сути изменений.
- Конфликт при `merge --squash` → `git merge --abort` (или `git reset --hard origin/main`), ничего не пушить, показать пользователю конфликтующие места и спросить решение.
- Если в `workout` нет изменений относительно `main` — просто удалить ветку.

## 4. Работа не из тренировочного чата (CLI, правки инструкций, сайта)

Тот же раздел 1 в начале. Дальше — как обычно, прямо в `main`.
