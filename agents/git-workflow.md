# Git: сохранение изменений

Репо — долгосрочная база журнала, всё в одной ветке `main`. Сайт читает данные прямо из репо по SHA последнего коммита (`agents/site.md`): запушенная правка видна на сайте сразу, а пересборка Pages запускается только при изменении кода — частота пушей данных не важна.

Пользователю про этот процесс не сообщать — делать молча. Говорить только о конфликтах.

## Правки журнала (`log/`, `requests/`, словари статистики)

1. **Перед каждой правкой** — не только в начале сессии, журнал мог измениться из другого чата:
   ```bash
   git pull --rebase origin main
   ```
2. **После каждой правки данных** (записанный факт, изменённый план, словари) — сразу коммит и пуш, ничего не копить:
   ```bash
   git add <изменённые файлы>
   git commit -m "<кратко, по-русски, по сути: «Т41: факт», «Жена: план 0014»>"
   git push origin main
   ```
   Пуш отклонён (в `main` появились чужие коммиты) — `git pull --rebase origin main` и пуш ещё раз.
3. **Конфликт при rebase** — `git rebase --abort`, ничего не пушить, показать пользователю конфликтующие места и спросить, как решить.

Окружение очистилось (новый чат, нет локальной копии) — склонировать заново: незапушенного не остаётся, раз пуш идёт после каждой правки.

## Код сайта и инструкции

Тот же `git pull --rebase origin main` перед правкой, коммит после. Пушит пользователь сам — пуш кода пересобирает Pages.
