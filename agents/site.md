# Сайт: хостинг, данные, оффлайн

## Хостинг — GitHub Pages через Actions

Живой адрес: **https://kmarkov563.github.io/sport/**. Публикует workflow `.github/workflows/pages.yml` (Settings → Pages → Source: GitHub Actions) — весь репозиторий как есть, без сборки. Запускается на пуш в `main` **только при изменении кода**: `*.html`, `*.js`, `assets/**`, `technique.json`, `muscle-map.json`, `home/**`, сам workflow; плюс вручную (Actions → Run workflow). Пуш только в `log/**` сборку не запускает.

Браузер держит HTML с Pages до 10 минут (`cache-control: max-age=600`): сразу после деплоя может открыться старая страница — помогает жёсткое обновление.

## Данные — из репозитория по SHA

`assets/data.js` → `fetchData(path)`: SHA последнего коммита `main` через GitHub API (один запрос на загрузку страницы, SHA помнится 30 с в `sessionStorage`), затем файл с `raw.githubusercontent.com/kmarkov563/sport/<sha>/<path>`. Адрес по SHA неизменяем — кэш raw старое не отдаёт, новый пуш виден после перезагрузки страницы.

Фолбэки: API недоступен или лимит (60 запросов в час на IP без авторизации) → последний удачный SHA из `localStorage` → если его нет, относительный путь (файлы деплоя Pages, могут быть старыми).

Все страницы грузят JSON только через `fetchData`; пути — относительно корня репо. Локально (Live Server) данные тоже приходят из GitHub — незапушенные правки `log/` не видны, код страниц и `assets/*.js` — локальный. Из `file://` страницы не работают.

## Статистика

Сводку микроцикла (`coach.html`) и прогресс (`report.html`) считает `assets/stats.js` из файлов планов; AI ведёт только словари — `agents/stats-dictionaries.md`.

## Оффлайн — `sw.js`

Сначала сеть, без сети — сохранённая копия с заголовком `X-Offline: 1` (страница показывает баннер). Перехватывает запросы к сайту и к raw-данным репозитория. Raw-файл хранится в кэше под адресом без SHA — одна, последняя загруженная версия каждого файла. Оффлайн открывается то, что хоть раз загружалось онлайн. После изменения состава `PRECACHE` или логики — поднять `CACHE`.

## Проверку в браузере делает пользователь

Не проверять изменения в браузере: без `claude-in-chrome`, без локального http-сервера, без скриншотов. После правок страниц / JSON-планов описать, что изменено, и остановиться — пользователь сам открывает страницу и сообщает, если что-то не работает.
